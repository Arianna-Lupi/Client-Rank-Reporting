<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Internet → /api/cron/daily-report | Disparo externo no autorizado; el handler exige Bearer CRON_SECRET antes de cualquier trabajo |
| Handler → mensaje de Slack / logs | El bot token, el CRON_SECRET y report.message nunca deben aparecer en el post ni en logs |
| Reintentos del cron → Redis | Reinvocaciones dentro de la hora 9:00 podrían duplicar; claimDailyReport las bloquea |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-04 | Spoofing | GET handler (auth) | mitigate | isAuthorizedCron(req.headers, cfg.cronSecret) → 401 antes de cualquier trabajo |
| T-04-05 | Information disclosure | console.error / postMessage | mitigate | Nunca interpolar token, secret ni report.message en logs ni en el post; mensajes genéricos |
| T-04-06 | Denial of service / duplicación | claim antes de postear | mitigate | claimDailyReport(dateKey) atómico; corrida ya reclamada responde 200 sin postear |
| T-04-07 | Availability (un cliente rompe el reporte) | iteración de clientes | mitigate | status 'error' → continue; postMessage en try/catch por cliente; un fallo no aborta la corrida |
| T-04-SC | Tampering | npm installs | accept | No se agregan dependencias (reusa fetch nativo + @upstash/redis ya presente) |
</threat_model>
