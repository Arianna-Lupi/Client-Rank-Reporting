<objective>
Compose the phase into its single user-facing capability: `getClientReport(siteUrl, fetch?)` in `lib/report.ts` (RPT-04). It calls the fetcher, resolves the comparable pair, computes the deltas, and returns a discriminated union — `ok` | `insufficient_data` | `no_data` | `error` — that NEVER throws on missing/partial data and NEVER leaks a secret in the error case. The fetcher defaults to `fetchDailyMetrics` (production) but is injectable, so every branch is unit-tested offline.

Purpose: This is the thin top of the slice — the function Phase 4's cron calls once per active client to get a render-ready result. It turns the pure math + the live fetch into a single safe, total function.
Output: `lib/report.ts` (+ test). `npm test` and `npm run typecheck` pass.
</objective>

## Phase Goal

**As a** daily reporting system, **I want to** ask for one property's report and always get back a clear, structured result (movement, "sin datos", or a safe error), **so that** Phase 4 can post one Block Kit message per client every morning without a single code path that crashes or shows a nonsense delta.

> This plan is the MVP vertical slice that closes Phase 3: after it lands, a caller can invoke `getClientReport` end-to-end (with the real `fetchDailyMetrics` default) and receive a fully-typed report.

lib/report.ts:
```typescript
import type { DailyMetricRow, MetricDeltas } from './metrics.js';

/** A fetcher of per-date rows for a property. Injectable for tests; defaults to fetchDailyMetrics. */
export type DailyMetricsFetcher = (siteUrl: string) => Promise<DailyMetricRow[]>;

/** Render-ready result for one property. Total: every input maps to exactly one variant. */
export type ClientReport =
  | { status: 'ok'; date: string; deltas: MetricDeltas }   // date = the last available day
  | { status: 'insufficient_data'; date?: string }          // <2 days; date = the single day if present
  | { status: 'no_data' }                                    // zero rows
  | { status: 'error'; message: string };                    // fetcher threw; message is secret-free

/** Compose fetch -> resolve -> compute into a never-throwing report. */
export function getClientReport(
  siteUrl: string,
  fetch?: DailyMetricsFetcher,
): Promise<ClientReport>;
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| fetcher (GSC I/O) -> getClientReport | The fetcher can throw (auth/network); the failure must become a safe status, never an unhandled rejection. |
| caught error -> returned message -> Slack | The error message flows to Phase 4 and into a channel post; it must be a fixed generic string, never the raw error/credential. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-06 | Information Disclosure | getClientReport catch block | mitigate | Returns a fixed generic Spanish message; the caught error's message/stack is never interpolated into the result. Asserted by the `not.toContain('PRIVATE_KEY')` test. |
| T-03-07 | Denial of Service | getClientReport | mitigate | Total function: missing/partial data maps to insufficient_data/no_data, fetcher throws map to error — no unhandled rejection can crash the Phase 4 cron loop mid-report. |
| T-03-08 | Tampering | injected fetcher | accept | The default fetcher is the audited fetchDailyMetrics; only trusted Phase 4 code injects an alternative. No untrusted caller path exists in v1. |
</threat_model>
